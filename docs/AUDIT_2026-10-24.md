## Befunde

### Kritisch

**K1. Verschieben über Laufwerke kann Daten verlieren** (`shell/SHELL.C:199`, `:204`)
```c
while ((n = FileRead(a, p, 4096)) > 0) if (FileWrite(b, p, n) != n) { e = RD_ERR_FULL; break; }
...
if (weg) { if (attr & FA_RDONLY) FileAttr(qv, 0, 1); e = FileDelete(qv); }
```
`FileRead` liefert bei einem Lesefehler 0 (`kern/FILE.C:110`). Die Schleife hält das für das Dateiende.
Die Kopie ist dann unvollständig, und beim Verschieben wird die Quelle trotzdem gelöscht (z. B. defekter
Sektor auf Diskette). Vorschlag: vor der Schleife `SetLastError(0)`, nach der Schleife `LastError()`
prüfen. Bei einem Fehler die Kopie löschen und die Quelle behalten. Optional die Größe vergleichen.

**K2. Diskettenwechsel-Abfrage des Kerns läuft über BIOS-Text im Grafikmodus** (`kern/FILE.C:14-31`, `:39-41`, `kern/MOD.C:167`)
```c
static void bios_out(LPCSTR s) { for (; *s; s++) { kr.ax = 0x0E00 | (BYTE)*s; ... rd_int(0x10, &kr); } }
```
Der Kommentar sagt „bis Phase 4 ein Text über das BIOS, danach ein Dialog“, umgestellt wurde das nie.
Auf HGC ist der Text unsichtbar, und RD2 wartet scheinbar hängend auf Eingabe oder Esc. Auf CGA und VGA
schreibt das BIOS an die Cursorstelle ins Bild, scrollt unter Umständen und stellt den Bildschirm nicht
wieder her. Weil 360-KB-Verteilung Diskettenwechsel bedeutet (Diskette 2 mit Werkzeugen), ist das
zentral. Die Tests merken es nicht, weil sie die Abfrage über COM1 beantworten. Vorschlag: Abfrage über
einen Rückruf aus RDUSER/RDCTL (MsgBox), BIOS-Text nur vor dem Grafikstart. Außerdem ist der Text fest
deutsch und nicht in DE.LNG/EN.LNG.

**K3. RD2.INI kann bei einem Lesefehler überschrieben werden** (`kern/FILE.C:259-268`, `:342-366`)
```c
if ((f = FileOpen(file, FO_READ)) >= 0) { pn = FileRead(...); ... }
k_lasterr = 0;
return 1;
```
`pload` behandelt jeden Fehler beim Öffnen wie „Datei gibt es nicht“. Ist die Diskette kurz nicht lesbar
oder kommt ein Lesefehler, schreibt `ProfileSetStr` eine neue Datei, die nur den einen Schlüssel enthält.
Alle anderen Einstellungen sind weg. Vorschlag: Nur `RD_ERR_NOTFOUND` als leere Datei behandeln, sonst
abbrechen. Auch `FileRead` < erwartet als Fehler werten.

### Mittel

**M1. ProfileSetStr meldet Erfolg, obwohl nichts eingetragen wurde** (`kern/FILE.C:327-361`). Die
Rückgabewerte von `pput` (0 bei mehr als PMAX+500) werden nicht geprüft, die Datei wird unverändert
zurückgeschrieben und 0 geliefert. Vorschlag: Fehler von `pput` weitergeben (`RD_ERR_FULL`).

**M2. Jeder Profilzugriff liest die ganze Datei neu und holt 16,5 KB festen Speicher** (`kern/FILE.C:263`).
Auf Diskette kosten viele `ProfileGetStr` beim Start Zeit, und 16,5 KB fest können bei knappem Speicher
fehlschlagen (dann kommt still der Vorgabewert). Vorschlag: Puffer an die Dateigröße anpassen und einen
kleinen Zwischenspeicher für die zuletzt gelesene Datei.

**M3. Aktuelles Verzeichnis und Laufwerk sind für alle Programme gemeinsam** (`kern/FILE.C:151-156`).
`DirChange` ändert den DOS-Zustand für alle Tasks. Programm A wechselt, Programm B öffnet dann eine
relative Datei im falschen Ordner. Vorschlag: Pro Task ein Arbeitsverzeichnis im Kern merken und
relative Namen dort auflösen, oder in SPEC.md festlegen: nur vollständige Pfade.

**M4. RDFORMAT kann mehrfach gleichzeitig laufen** (`disk/RDFORMAT.C:93-106`). Während des Formatierens
läuft die Nachrichtenschleife weiter, über das Laufwerksmenü lässt sich ein zweites RDFORMAT starten,
auch für dasselbe Laufwerk. Vorschlag: Sperre in RDDISK.MOD (Laufwerk belegt) oder nur eine Instanz.

**M5. FAT16 über 32 MB ist ungetestet** (`test/hdd.sh`). Getestet ist nur eine 20-MB-Platte. Ab 32 MB
(Typ 06h) laufen INT 25h/26h mit Paket (CX = FFFFh), das ist ein eigener Weg in `disk/RDDISK.C:16-19`.
Vorschlag: zweiter Lauf in hdd.sh mit 100 MB und eine Platte mit 2 Partitionen.

**M6. RDDISK.MOD gibt jedem Programm vollen Plattenzugriff** (`disk/RDDISK.C:39-41`). INT 13h, 25h, 26h
und alle IOCTL-Unterfunktionen (440Dh mit Spur schreiben und formatieren) sind frei. Für FORMAT und FDISK
nötig, aber jedes RD2-Programm kann das Modul laden. Vorschlag: Für jetzt in SPEC.md dokumentieren,
später Freigabe nur für signierte Werkzeuge oder eine Rückfrage beim ersten Schreibzugriff auf eine
Festplatte.

**M7. Englisches Menü: doppelte Taste C im Menü File** (`shell/SHELL.RC:61`, `:68`): `&Copy` und
`&Close`. Vorschlag: `C&lose`.

**M8. Unfertiger RDFDISK-Code: Lage auf großen Platten falsch** (`disk/fdglue.c`, nicht eingecheckt).
Startsektoren der logischen Laufwerke und des freien Platzes werden über CHS berechnet. Ab 1024 Zylindern
stehen dort Höchstwerte, der Balken zeigt dann falsche Lagen. Vorschlag: aus `rel_sect` der
EMBR-Kette rechnen (`next_ext[]`). Wird beim Fertigstellen von RDFDISK erledigt.
Behoben 24.10.: Start der logischen Laufwerke = Beginn der erweiterten + `next_ext[i-1].rel_sect` + eigener `rel_sect`. Test `test/fdisk.sh` (Fall zwei).

## Teil 2a: Kern (TASK, MOD, KASM, RUNDOS, RDSWAP)

Geprüft am 24.10.2026: Umschalten (kooperativ und Zeitscheibe), Eingabe im Zeitgeber, Notbeenden,
Laden von Programmen und Modulen, Sprungstücke, Verwerfen und Nachladen (Diskette und XMS), INT 8/9/23/24,
RunDos mit Auslagerung. Ohne Befund: Sichern der Flags beim Umschalten (`rd_swtch`), Reihum-Suche in
`schedule`, Aufräumen beendeter Tasks, Sperre gegen Verwerfen während eines Modulaufrufs, Schreibfehler
beim Auslagern (RunDos meldet „kein Speicher“, nichts geht verloren).

**M9. Zeitzähler wird ohne Sperre gelesen** (`kern/TASK.C:28-33`). `rd_ticks` ist 32 Bit, C liest es in
zwei Wortzugriffen. Kommt INT 8 genau dazwischen, während das untere Wort überläuft (alle 65536 Takte,
etwa alle 15 Minuten), springt die Zeit um rund 15 Minuten vor. Zusätzlich teilen sich Zeitgeber-Interrupt
und Programm den Zwischenspeicher `lt`/`lm`. Folge: ein Zeitgeber, der genau dann gestellt wird, schweigt
bis zu 15 Minuten (Uhr, Fortschritt, Blinken). Selten, aber auf einem Rechner, der lange läuft, möglich.
Vorschlag: Lesen und Zwischenspeicher mit `pushf/cli … popf` schützen (etwa 8 Bytes, passt in die 16 freien).
Behoben 24.10.: `ms_now` ist jetzt Assembler in KASM.ASM und liest `rd_ticks` samt Zwischenspeicher mit gesperrten Interrupts (`pushf/cli … popf`). Gerechnet wird `(t*879)>>6` mit 48 Bit; die alte Formel lief nach etwa 14 Tagen Laufzeit über (Sprung der Zeit), die neue erst bei 2^32 ms (49 Tage). Kleiner als die C-Fassung, dadurch passt auch G12; der Kern hat jetzt 12 Bytes frei.

**M10. Speicherresidentes DOS-Programm über RunDos startet den Rechner neu** (`kern/RDSWAP.ASM:96-120`).
Bleibt ein Programm resident (Maustreiber, DOSKEY, ein TSR-Spiel-Lader) oder hinterlässt es belegten
Speicher, kann der Rest den Kern nicht an dieselbe Stelle zurückholen. Er zeigt dann eine Meldung und ruft
INT 19h: alle offenen RD2-Programme sind ohne Sichern weg. Vorschlag: statt Neustart wie im
Diskettenbetrieb RD.EXE frisch starten (Sitzung verloren, aber kein Neustart und DOS bleibt sauber), dazu
ein Hinweis. Kostet keinen Kernspeicher (RDSWAP.BIN).

**G10. Notbeenden mitten in einem Rückruf aus einem Modul** (`kern/TASK.C:180-195`). Hängt ein Programm in
seiner Fensterfunktion, während RDCTL einen Dialog führt, wird es beendet; `mod_unwind` gibt die Sperre
frei, aber der Zustand im Modul (laufender Dialog) bleibt halb. Bei RDCTL prüfen (Teil 2c).
Geprüft 24.10. (Teil 2c): RDCTL und RDCTLX halten keinen Dialogzustand im Modul. Die Dialogschleife steht auf dem Stapel des Programms, die Fenster gehören dem Programm und verschwinden mit ihm, die Vorlage ist ein Block des Programms. Einzige Folge: Ist der Besitzer des Dialogs ein Fenster eines anderen Programms (ungewöhnlich), bleibt es gesperrt. Dazu kommt G18 (RDCTLX bleibt eingetragen). Kein Handlungsbedarf.

**G11. Aufräumen nach präemptivem Umschalten läuft im Zeitgeber-Interrupt** (`kern/TASK.C:72`, `reap`).
Fenster eines beendeten Programms neu zeichnen und Dateien schließen geschieht dann mit gesperrten
Interrupts. Erlaubt (DOS ist nicht aktiv), aber die Uhr kann Takte verlieren. Nur beobachten.

**G12. Programmgröße ohne Überlaufprüfung** (`kern/TASK.C:248`). `Bildgröße + minalloc` kann bei einer
kaputten Datei über 64K Paragraphen laufen, dann wird zu wenig Speicher geholt. Kopf und Prüfsumme
müssen dafür schon stimmen. Gering, Prüfung kostet etwa 6 Bytes.
Behoben 24.10.: Überlauf wird erkannt, `RD_ERR_FORMAT`. WINTEST startet UEBER.EXE (LEER.EXE mit Mindestzuteilung FFFFh, beim Bauen erzeugt): ohne die Korrektur FEHLER, mit ok.

## Teil 2b: RDGDI, RDGDIX, Grafiktreiber

Geprüft am 24.10.2026: Mauszeiger im Interrupt (Abstimmung über `gbusy` und `cli`), Zeiger am Bildrand,
Auswahl des Zeichenziels und Clipliste, BitBlt (Abschneiden an der Quelle, Überlappen von unten),
StretchBlt, Bitmaps, Füllen, Treibererkennung (Hercules über Strahlrücklauf, CGA über den 6845) und
Rückkehr in den Textmodus. Ohne Befund: Zeiger und Zeichnen kommen sich nicht in die Quere, Cliplisten
sind auf 16 Rechtecke begrenzt, StretchBlt rechnet ohne Division.

**M12. Zeichenflächen beendeter Programme bleiben belegt** (`user/RDUSER.C:1119-1128`, `gdi/RDGDI.C:568`).
Beim Programmende gibt RDUSER Fenster, Klassen und Menüs frei, aber nicht die Fenster-DCs (6 Plätze,
`NSLOT`) und RDGDI nicht die DCs des Programms (24 Plätze). `owner` wird zwar eingetragen, aber nie
benutzt. Wird ein Programm beim Zeichnen beendet (Notbeenden, Absturz) oder vergisst es `ReleaseDC`, ist der
Platz weg. Nach sechs solchen Fällen kann kein Fenster mehr zeichnen, die ganze Oberfläche steht.
Vorschlag: beim Programmende in RDUSER die Plätze des Programms und in RDGDI alle DCs mit diesem `owner`
freigeben. Etwa 30 Bytes, RDUSER hat nur noch 16 frei.
Behoben 24.10.: Beim Programmende gibt RDUSER alle DCs des Programms frei (samt Fensterplatz). Den Platz (50 Bytes) haben zwei zusammengelegte Schleifen und ein gemeinsamer Fehlerausgang gebracht, RDUSER hat jetzt 52 Bytes Reserve. WINTEST beendet 25 Programme mit offenem DC und prüft, dass `GetDC` danach noch geht: ohne die Korrektur FEHLER, mit ok.

**G13. Jeder Speicherblock wird als Bitmap angenommen** (`gdi/RDGDI.C:578`, `sel`, `zget`). `BmpDC` prüft
nur, ob der Block existiert. Ein falsches Handle (gewöhnlicher Speicherblock) liefert unsinnige Breite und
Höhe, das Zeichnen schreibt dann über das Blockende hinaus. Vorschlag: Kopf prüfen (`bpr == (w+7)/8`, Größe
passt in `MemSize`). Etwa 20 Bytes.
Nicht behoben (24.10.): Die Prüfung kostet in RDGDI 120 Bytes statt 20, RDGDI hätte danach nur noch 36 Bytes frei. Ein falsches Handle ist ein Programmierfehler, kein Bedienfehler. Bleibt offen für den nächsten Umbau von RDGDI.

**G14. Clipliste veraltet bei gehaltenem DC über einen Taskwechsel**. Hält ein Programm einen Fenster-DC,
wird umgeschaltet und ein anderes Programm schiebt ein Fenster darüber, zeichnet das erste mit der alten
Clipliste in das fremde Fenster. Das nächste Neuzeichnen behebt es. Vorschlag: RDUSER berechnet bei jeder
Fensteränderung die offenen Plätze neu.
Offen (24.10.): Die Korrektur braucht in RDUSER Fenster und Art je Platz und einen Aufruf bei jeder Fensteränderung, geschätzt 60 bis 80 Bytes; RDUSER hat 52 frei. Das nächste Neuzeichnen behebt den Fehler. Mit dem nächsten Umbau von RDUSER.

**G15. Füllen (FloodFill) mit Grenzen** (`gdi/RDGDIX.C:102-139`). Der Stapel hat 1024 Punkte; läuft er
über, bleiben still Lücken. Die Suche liest auch verdeckte Bildpunkte fremder Fenster und kann so getrennte
Teile des eigenen Fensters erreichen (gezeichnet wird geclippt). Selten, nur beobachten.

## Teil 2c: RDCTL, RDCTLX

Geprüft am 24.10.2026: Dialogschleife, Aufbau aus der Vorlage, Eingabefeld, Liste, Rückrufe ins Programm,
Dateidialog (Pfade, Muster, Vorlage im Speicher). Ohne Befund: Eingabefeld und Liste schreiben nie über
ihren Speicher hinaus, alle Zeichenkettenkopien im Dateidialog sind begrenzt, die Dialogschleife reicht
ein Programmende (`PostQuit`) weiter. Zu G10: Wird ein Programm mitten im Dialog notbeendet, räumt RDUSER
Dialog und Fenster ab und der Kern den Speicher. Nur ein Besitzerfenster eines anderen Programms bliebe
gesperrt (kommt bisher nicht vor).

**G16. Dateidialog kürzt zu lange Pfade still** (`ctl/RDCTLX.C:120`). Passt der gewählte Pfad nicht in
`fd->len`, wird er abgeschnitten und das Programm speichert unter einem falschen Namen. Vorschlag: zu lange
Pfade mit Meldung ablehnen.
Behoben 24.10.: zu langer Pfad, Meldung „Der Pfad ist zu lang.“ (Text 16 in DE/EN.LNG), der Dialog bleibt offen.

**G17. Titel des Dateidialogs ohne Längengrenze** (`ctl/RDCTLX.C:151`). Die Vorlage liegt in 512 Bytes,
ein Titel ab etwa 140 Zeichen schreibt darüber hinaus. Vorschlag: Titel auf 60 Zeichen begrenzen.
Behoben 24.10.: Titel wird auf 60 Zeichen begrenzt.

**G18. Von beendeten Programmen geladene Module bleiben geladen** (`kern/MOD.C`, Zähler `refs`). Der Zähler
gilt für alle Programme gemeinsam. Endet ein Programm ohne `ModFree` (vergessen, Notbeenden im Dateidialog),
bleibt das Modul eingetragen. Der Code ist verwerfbar, der Speicher kommt also bei Bedarf zurück, der
Modulplatz nicht. Vorschlag: Ladevorgänge pro Programm merken und beim Ende freigeben.
Offen (24.10.): Ladevorgänge pro Programm zu merken kostet im Kern Code und je Modul ein Wort, der Kern hat 12 Bytes frei. Der Speicher kommt zurück (verwerfbar), nur der Modulplatz nicht. Mit dem nächsten Umbau des Kerns.

**G19. Texte still auf 32 Zeichen gekürzt** (`ctl/RDCTL.C:307`, `ladd`). Der Vorgabetext eines
Eingabefelds aus der Vorlage wird auf 32 Zeichen gekürzt, obwohl das Feld 80 fasst; Listeneinträge auf 32.
Vorschlag: Vorgabetext bis 80 Zeichen übernehmen, die 32 bei Listen in FUNKTIONEN.md nennen.
Geklärt 24.10.: Die Grenze kommt aus RDUSER (Fenstertexte höchstens 31 Zeichen, mehr kostet Speicher je Fenster). In SPEC.md beschrieben: längere Vorgaben per `DlgSetText`, Listeneinträge höchstens 32 Zeichen.

## Teil 2d: RD2SETUP

Geprüft am 24.10.2026: Erkennung, Lesen und Schreiben von RD2.INI, Eingabe des Ziels, Kopieren,
AUTOEXEC.BAT mit Sicherung. Ohne Befund: Eingaben und Zeilenpuffer sind begrenzt, AUTOEXEC.RDA wird vor

**M13. Installation kopierte RDSWAP.BIN nicht** (`setup/RD2SETUP.C:331`), behoben 24.10. Kopiert wurden
nur EXE, MOD, DRV, FNT und LNG. Auf einer Festplatteninstallation konnte RD2 deshalb keine DOS-Programme
starten. Jetzt auch `*.BIN`; test/install.sh prüft RDSWAP.BIN mit (ok).

**G20. Große Dateien werden gekürzt** (`ini_schreiben`, `autoexec`). RD2.INI wird nur bis 6 KB gelesen
und neu geschrieben, der Rest geht verloren. Bei einer AUTOEXEC.BAT über 6 KB wird ein vorhandener Eintrag
dahinter nicht gefunden und doppelt angehängt. Vorschlag: bei voller Datei nicht schreiben, sondern melden.
Behoben 24.10.: RD2.INI und CONFIG.SYS über 6 KB werden nicht geändert, das Setup meldet es.

**G21. Setup trägt RD.EXE in AUTOEXEC.BAT ein**, laut Entscheidung vom 21.10. soll RD.EXE als Shell laufen
(`SHELL=` in CONFIG.SYS, kein COMMAND.COM). Über AUTOEXEC bleibt COMMAND.COM resident (einige KB). Zum
Abstimmen: Shell-Eintrag in CONFIG.SYS (mit Sicherung) statt AUTOEXEC.
Umgesetzt 24.10. (Entscheidung Karsten): RD.EXE wird als `SHELL=…RD.EXE /P` in CONFIG.SYS eingetragen, die AUTOEXEC.BAT bleibt unverändert. Neues System (weder CONFIG.SYS noch AUTOEXEC.BAT): ohne Rückfrage, CONFIG.SYS enthält nur `SHELL=` und den Maustreiber. Bestehendes DOS: Rückfrage, Sicherung CONFIG.RDA, alte `SHELL=` bleibt als `REM` stehen, jede Programmzeile der AUTOEXEC.BAT wird einzeln abgefragt und als `INSTALL=` übernommen (`LH` entfällt, Pfad wird im PATH gesucht), Hinweis, dass SET und PATH dann nicht mehr gelten. Maus: CTMOUSE (Diskette 1) bei serieller/PS/2-Maus, bei Bus-/InPort-Maus fragt das Setup nach dem Herstellertreiber und kopiert ihn ins RD2-Verzeichnis. test/install.sh prüft beide Fälle (ok). RD2SETUP.EXE dafür 24 -> 27 KB (Datei, nicht resident).

**G22. Ziel mit fehlenden Zwischenordnern**. `mkdir` legt nur die letzte Ebene an; bei `C:\SPIELE\RD2`
ohne `C:\SPIELE` schlagen alle Kopien fehl und es erscheint nur "FEHLER". Vorschlag: Ordner Ebene für Ebene
anlegen, sonst klar melden.
Behoben 24.10.: Ordner werden Ebene für Ebene angelegt, sonst Meldung „Zielordner kann nicht angelegt werden.“ test/install.sh installiert nach C:\SPIELE\RD2 (ok).
