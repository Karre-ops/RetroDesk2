## Befunde

### Kritisch

**K1. Verschieben über Laufwerke kann Daten verlieren** (`shell/SHELL.C:199`, `:204`)
```c
while ((n = FileRead(a, p, 4096)) > 0) if (FileWrite(b, p, n) != n) { e = RD_ERR_FULL; break; }
...
if (weg) { if (attr & FA_RDONLY) FileAttr(qv, 0, 1); e = FileDelete(qv); }
```
`FileRead` liefert bei einem Lesefehler 0 (`kern/FILE.C:110`). Die Schleife hält das für das Dateiende.
Die Kopie ist dann unvollständig, und beim Verschieben wird die Quelle trotzdem gelöscht (z. B. defekter
Sektor auf Diskette). Vorschlag: vor der Schleife `SetLastError(0)`, nach der Schleife `LastError()`
prüfen. Bei einem Fehler die Kopie löschen und die Quelle behalten. Optional die Größe vergleichen.

**K2. Diskettenwechsel-Abfrage des Kerns läuft über BIOS-Text im Grafikmodus** (`kern/FILE.C:14-31`, `:39-41`, `kern/MOD.C:167`)
```c
static void bios_out(LPCSTR s) { for (; *s; s++) { kr.ax = 0x0E00 | (BYTE)*s; ... rd_int(0x10, &kr); } }
```
Der Kommentar sagt „bis Phase 4 ein Text über das BIOS, danach ein Dialog“, umgestellt wurde das nie.
Auf HGC ist der Text unsichtbar, und RD2 wartet scheinbar hängend auf Eingabe oder Esc. Auf CGA und VGA
schreibt das BIOS an die Cursorstelle ins Bild, scrollt unter Umständen und stellt den Bildschirm nicht
wieder her. Weil 360-KB-Verteilung Diskettenwechsel bedeutet (Diskette 2 mit Werkzeugen), ist das
zentral. Die Tests merken es nicht, weil sie die Abfrage über COM1 beantworten. Vorschlag: Abfrage über
einen Rückruf aus RDUSER/RDCTL (MsgBox), BIOS-Text nur vor dem Grafikstart. Außerdem ist der Text fest
deutsch und nicht in DE.LNG/EN.LNG.

**K3. RD2.INI kann bei einem Lesefehler überschrieben werden** (`kern/FILE.C:259-268`, `:342-366`)
```c
if ((f = FileOpen(file, FO_READ)) >= 0) { pn = FileRead(...); ... }
k_lasterr = 0;
return 1;
```
`pload` behandelt jeden Fehler beim Öffnen wie „Datei gibt es nicht“. Ist die Diskette kurz nicht lesbar
oder kommt ein Lesefehler, schreibt `ProfileSetStr` eine neue Datei, die nur den einen Schlüssel enthält.
Alle anderen Einstellungen sind weg. Vorschlag: Nur `RD_ERR_NOTFOUND` als leere Datei behandeln, sonst
abbrechen. Auch `FileRead` < erwartet als Fehler werten.

### Mittel

**M1. ProfileSetStr meldet Erfolg, obwohl nichts eingetragen wurde** (`kern/FILE.C:327-361`). Die
Rückgabewerte von `pput` (0 bei mehr als PMAX+500) werden nicht geprüft, die Datei wird unverändert
zurückgeschrieben und 0 geliefert. Vorschlag: Fehler von `pput` weitergeben (`RD_ERR_FULL`).

**M2. Jeder Profilzugriff liest die ganze Datei neu und holt 16,5 KB festen Speicher** (`kern/FILE.C:263`).
Auf Diskette kosten viele `ProfileGetStr` beim Start Zeit, und 16,5 KB fest können bei knappem Speicher
fehlschlagen (dann kommt still der Vorgabewert). Vorschlag: Puffer an die Dateigröße anpassen und einen
kleinen Zwischenspeicher für die zuletzt gelesene Datei.

**M3. Aktuelles Verzeichnis und Laufwerk sind für alle Programme gemeinsam** (`kern/FILE.C:151-156`).
`DirChange` ändert den DOS-Zustand für alle Tasks. Programm A wechselt, Programm B öffnet dann eine
relative Datei im falschen Ordner. Vorschlag: Pro Task ein Arbeitsverzeichnis im Kern merken und
relative Namen dort auflösen, oder in SPEC.md festlegen: nur vollständige Pfade.

**M4. RDFORMAT kann mehrfach gleichzeitig laufen** (`disk/RDFORMAT.C:93-106`). Während des Formatierens
läuft die Nachrichtenschleife weiter, über das Laufwerksmenü lässt sich ein zweites RDFORMAT starten,
auch für dasselbe Laufwerk. Vorschlag: Sperre in RDDISK.MOD (Laufwerk belegt) oder nur eine Instanz.

**M5. FAT16 über 32 MB ist ungetestet** (`test/hdd.sh`). Getestet ist nur eine 20-MB-Platte. Ab 32 MB
(Typ 06h) laufen INT 25h/26h mit Paket (CX = FFFFh), das ist ein eigener Weg in `disk/RDDISK.C:16-19`.
Vorschlag: zweiter Lauf in hdd.sh mit 100 MB und eine Platte mit 2 Partitionen.

**M6. RDDISK.MOD gibt jedem Programm vollen Plattenzugriff** (`disk/RDDISK.C:39-41`). INT 13h, 25h, 26h
und alle IOCTL-Unterfunktionen (440Dh mit Spur schreiben und formatieren) sind frei. Für FORMAT und FDISK
nötig, aber jedes RD2-Programm kann das Modul laden. Vorschlag: Für jetzt in SPEC.md dokumentieren,
später Freigabe nur für signierte Werkzeuge oder eine Rückfrage beim ersten Schreibzugriff auf eine
Festplatte.

**M7. Englisches Menü: doppelte Taste C im Menü File** (`shell/SHELL.RC:61`, `:68`): `&Copy` und
`&Close`. Vorschlag: `C&lose`.

**M8. Unfertiger RDFDISK-Code: Lage auf großen Platten falsch** (`disk/fdglue.c`, nicht eingecheckt).
Startsektoren der logischen Laufwerke und des freien Platzes werden über CHS berechnet. Ab 1024 Zylindern
stehen dort Höchstwerte, der Balken zeigt dann falsche Lagen. Vorschlag: aus `rel_sect` der
EMBR-Kette rechnen (`next_ext[]`). Wird beim Fertigstellen von RDFDISK erledigt.

### Gering

- **G1.** `drv/GFX1.C:91` unerreichbarer Code (Warnung W201), aufräumen.
- **G2.** Gleiche Hilfsfunktionen mehrfach: `slen` in 4 Dateien, `scpy` in 4, `scat` in 3, `gleich` in 3.
  Vorschlag: einmal in RD2.LIB (kostet je Programm nur, was es benutzt).
- **G3.** Kommentar veraltet: `disk/RDDISK.C:2` nennt noch „FORMAT, SYS“, SYS ist seit 24.10. entfernt.
- **G4.** Überschreiben beim Kopieren fragt pro Datei, ohne „Alle“ (`shell/SHELL.C:189-192`). Bei vielen
  Dateien lästig.
- **G5.** Verschieben auf demselben Laufwerk benennt um, ohne zu fragen, ob das Ziel existiert
  (`shell/SHELL.C:232`). DOS lehnt ab, die Meldung zeigt dann nur einen Fehlercode.
- **G6.** Pfade werden still abgeschnitten (`scpy`/`scat` mit `sizeof qv` = 80). DOS lehnt so lange Pfade
  ohnehin ab, beim rekursiven Löschen sollte aber vorher eine klare Meldung kommen.
- **G7.** Text `shell/SHELL.RC:41` „%s Eintrag/Einträge wirklich löschen?“: besser zwei Texte (1 Eintrag /
  n Einträge).
- **G8.** Laufwerksmenü ohne „Festplatte einrichten…“. Eine leere Platte hat keinen Buchstaben, RDFDISK
  braucht einen eigenen Einstieg (geplant).
- **G9.** Timer werden beim `DestroyWindow` nicht entfernt (`user/RDUSER.C`, `weg`). Durch die Generation im
  Handle harmlos, kostet aber Plätze in der Timertabelle.
