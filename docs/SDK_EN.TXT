RetroDesk 2 - SDK (disk 4)
==========================

With the SDK you write your own programs for RetroDesk 2 (RD2) in C
(Open Watcom), Turbo Pascal / Free Pascal or assembler. German version:
SDK.TXT.

  \SDK\RD2.H         types, constants, messages, structures
  \SDK\RD2API.H      all functions of the kernel and modules (fixed numbers)
  \SDK\RD2DRV.H      driver interface (graphics, sound, network)
  \SDK\RD2ORD.H      short form of the function numbers
  \SDK\RD2START.ASM  startup code for programs (wasm)
  \SDK\RD2MOD.ASM    startup code for modules (.MOD) and drivers (.DRV)
  \SDK\RD2.LIB       library (Open Watcom, medium model)
  \SDK\RDRC.EXE      resource compiler and linker (DOS, runs on the XT)
  \SDK\BEISPIEL\     HALLO.C and HALLO.RC: window, menu, mouse clicks; GESAMT.C,
                     VOLLTEST.C, VESATEST.C, VOLLMAUS.C, TAKTTEST.C, MIXTEST.C,
                     PRNTEST.C (referred to as apps/test/... below)
  \SDK\PASCAL.ZIP    unit RD2.PAS, examples, Pascal guide (German, packed)


1. Building a program (C, Open Watcom)
--------------------------------------

  wcc -0 -mm -os -s -zl -bt=dos -i=\SDK HALLO.C
  wasm -0 \SDK\RD2START.ASM
  wlink format dos name HALLO file RD2START,HALLO
        library \SDK\RD2.LIB,clibm.lib option nodefaultlibs
  RDRC HALLO.RC HALLO.EXE "Hallo"

-0 generates 8086 code (runs on the XT), -mm is the medium memory model.
Without resources use "-" instead of the .RC:  RDRC - HALLO.EXE "Hallo"

RDRC appends the RD2 block (name, type, API version, stack) and the
resources to the EXE. Switches:

  /T:P|M|D    program, module, driver (default P)
  /S:n        stack in bytes (default 4096)
  /K:n        additional memory in KB
  /V:0xMMmm   program version, /A:0xMMmm minimum RD2 version (0x0100)
  /F:n        flags
  /PAS        Pascal program (see below)

Running it again replaces the old appendix. Started under plain DOS an RD2
program prints "Dieses Programm benoetigt RetroDesk 2." and exits.


2. Structure of a program
-------------------------

  #include "RD2.H"
  short RDAPI RdMain(HINST inst, LPCSTR cmd, WORD show)
  {
      ... RegisterClass, CreateWindow ...
      while (GetMessage(&m)) DispatchMessage(&m);
      return 0;                     /* exit code */
  }

Window procedures are  DWORD RDCALLBACK proc(HWND, WORD msg, WORD p1, DWORD p2).
Pass everything you do not handle to DefWindowProc.
Important messages: M_CREATE, M_PAINT (BeginPaint/EndPaint), M_KEY (p1 =
key K_*), M_BUTTONDOWN, M_COMMAND (menu, button: p1 = id), M_TIMER,
M_CLOSE, M_DESTROY (then PostQuit).


3. Rules
--------

- All functions are far pascal, all pointers FAR. Handles are 16 bit,
  0 means "none" or error; LastError() gives the reason (RD_ERR_*).
- Text is code page 437, zero-terminated; length -1 = up to the 0.
- No direct DOS or BIOS calls, no own interrupt handlers.
  Files: FileOpen, FileRead, FileWrite ...; screen: GetDC, TextOut ...
- Allowed from the C library: string.h, ctype.h, math.h, stdlib.h without
  system/exit, sprintf. malloc and free go to MemFixed through RD2.LIB.
  Not allowed: printf, getch, fopen, graphics and interrupt functions.
- RD2 switches between programs while they run in their own code, but a
  program only receives input in its next GetMessage/PeekMessage. Do long
  work in pieces (M_TIMER) or call PeekMessage in between.
- Memory is tight (machines with at most 640 KB). Large data with MemAlloc (movable,
  MemLock before access, MemUnlock afterwards).
- Debug output with DbgPrint/DbgHex (COM1 or RD2DBG.TXT).


3a. Memory failures and swapping (API 2.1)
----------------------------------------
MemAlloc and MemRealloc return 0 on failure; MemLock returns a null pointer.
This may happen for a valid handle when its swapped data cannot be loaded.
Check every return value before dereferencing. A FAR pointer is valid only
until MemUnlock; do not retain locked pointers across TaskYield or waits.

LastError remains RD_ERR_NOMEM for allocation/swap failures, preserving
existing apps. After MemAlloc, MemLock, MemRealloc or MemFixed, MemError()
returns a per-task detail:
  MEMERR_NONE       successful operation / no memory failure
  MEMERR_RAM        no suitable RAM block or handle
  MEMERR_SWAPLIMIT  configured swap file limit
  MEMERR_RESERVE    disk full or free-space reserve reached
  MEMERR_DISK       read, write or free-space query failed
  MEMERR_SLOTS      all 32 swap slots occupied
Invalid handles still report RD_ERR_HANDLE; discarded data RD_ERR_NOTFOUND.
Capture both errors before further memory operations replace the detail.
MemFree/MemUnlock alone do not clear it. A successful allocation/access
clears it to MEMERR_NONE. Other tasks have separate details.

Cancel the requested action, release temporary buffers, and retain existing
documents/handles. Store a MemRealloc result in a second variable: failure
preserves the original handle. Do not retry indefinitely or allocate in
the failure path. Even a message box may fail for lack of memory; log with
DbgHex if needed. The SDK cannot protect an unchecked null dereference.
See sdk/SWAPSAFE.C (C, -0 -mm). MemError uses new API slot 0x042 and requires
kernel 2.1. Existing API slots/signatures are unchanged. The generated
Pascal unit provides the same function and constants.

Options > System provides swap on/off, maximum file KB (0 = no fixed limit)
and free disk reserve KB (0 = no reserve). Changes apply at the next RD2
start; current swapped data stays accessible until then. Defaults in
[System]: Auslagern=1, SwapMaxKB=0, SwapReserveKB=64. A KB is 1024 bytes.
Preset choices reach 16384 KB; existing INI values from 0 to 32767 KB are
preserved when opening the dialog. XMS is preferred; file size and reserve
limits do not apply to XMS. Existing file holes can be reused below the
reserve; only growth requiring additional disk clusters is rejected.


MemStats(MEMSTATS FAR *info), API 2.1 slot 0x043: current snapshot, returns
0 on success, RD_ERR_HANDLE for NULL, RD_ERR_BUSY during a swap callback.
Success preserves LastError/MemError and does not allocate memory.
ram_total/ram_free: RD2 arena bytes including UMB, excluding DOS/kernel
outside it. Used = total - free. Does not flush the profile cache.
swap_used: valid swapped payload bytes, file and XMS combined.
swap_file: written file extent, including holes and short writes; retained
on swap-in/free. swap_cached: unused file extents retained for reuse as a
buffer, without valid cached copies. Occupied file slots count at their
full extent, so internal slack is not counted as reusable.
swap_free: buffer plus possible file growth after the active limit and
free-space reserve, plus free XMS. Uses DOS 36h to query capacity. No file
growth on A:/B:. Only whole additional clusters count; existing last-cluster
slack is conservatively omitted. Unknown cluster formats add no growth.
Returns 0 with all 32 swap slots occupied. Fragmentation, block sizes and
I/O errors can still prevent allocation; always handle failures.
swap_maxkb/swap_reservekb: active startup settings in KiB, max=0 unlimited.
flags & MS_SWAP means RDAUSL loaded; otherwise all swap fields are zero.
Pending INI changes apply on restart. Task manager refreshes every second
and only shows swap current, buffer and free after the RAM line. Free
already includes the buffer. Usage/buffer round up, free rounds down to KiB.
Per-program values remain the load image size, labelled Bild/image.


4. Resources (.RC)
------------------

Source in code page 437, ";" starts a comment, text in "..." with
\t \n \" \\. Keywords are German.

  SPRACHE DE|EN|ALLE        language of the following resources
  TEXTE  id "Text" ... ENDE  (StrGet(inst, id), language from RD2.INI)
  MENU n
    POPUP "&File"
      ITEM "&Open..." 101 [GRAU] [HAKEN]    (GRAU = disabled, HAKEN = checked)
      TRENNER                               (separator)
    ENDE
  ENDE
  DIALOG n "Title" x y w h [style...]
    CLASS ["Text"] id x y w h [style...]
  ENDE
  ACCEL n   key shift id ... ENDE
  SYMBOL|BITMAP|CURSOR|SCHRIFT|DATEN n "file"   (icon, bitmap, cursor, font, data)

Dialog classes: BUTTON CHECK RADIO STATIC EDIT TEXT LIST COMBO SCROLL
PROGRESS GROUP. Styles: names from RD2.H (WS_*, ES_*), STANDARD = default
button, AN = checked, GRAU = disabled. Start a dialog with DialogRun(inst, n,
owner, proc, param); MenuSet(window, MenuLoad(inst, n)) sets a menu.


5. Refilling samples (ring buffer)
----------------------------------

SndSamplePlay(window, block, rate, SM_LOOP | SM_HALBE) plays the block in a
loop and reports every finished half as M_SOUNDDONE with p1 = 3 and p2 = 0
(first half) or 1 (second half). That half is then free to be refilled while
the other one plays. Without SM_LOOP the block ends as before with
M_SOUNDDONE p1 = 2. The message arrives through the message loop, not from
the interrupt. Make each half at least 1/10 s long (about 2 KB at 11025 Hz).
On the Sound Blaster there is a tiny gap at the middle of the block because
the driver restarts each chunk.


5a. System timer (145.6 Hz)
---------------------------------------------------------------
RD2 runs every machine at a fixed 145.6 Hz (6.9 ms, eight times the PC
clock; the time of day stays exact). Games and music register with a
divider instead of reprogramming the timer:
  static void RDAPI __loadds tick(void) { t++; }
  nr = TaktSet(tick, 1);     1 = 145.6 Hz, 2 = 72.8 Hz, 8 = 18.2 Hz ...
  TaktKill(nr);              otherwise at program exit
  TaktCount()                ticks since start (for polling)
Up to 8 callbacks at once. The callback runs in the interrupt: keep it short
(counters, advance sound), no API, no DOS, load your own DS (__loadds).
Longer work via a message. RD2/32: the same without __loadds; the callback
runs on its own 2 KB stack, no floating point. TaktSet does not work in
32-bit modules (0, RD_ERR_NOTSUP): the program registers. TimerSet (ms,
message M_TIMER) remains for everything leisurely.

5b. Mouse and keys in full screen
---------------------------------------------------------------
After ScreenAcquire and your own mode switch (ScreenMode, VESA):
  ScreenMouse(w, 320, 200);  mouse range 0..319 / 0..199
Mouse messages (M_MOUSEMOVE, M_BUTTONDOWN ...) then arrive at the window in
full-screen coordinates. The program draws the pointer itself. Call
ScreenMouse again after M_SCREENBACK (back from Alt+Tab). Keys for games:
KeyState(KS_SCAN + TS_LINKS) is 1 while the key is held, for all keys at
once (TS_* in RD2.H, otherwise the scan code). Arrow keys and keypad count
the same.

5c. Mixer (several sounds at once, Sound Blaster)
---------------------------------------------------------------
k = SndMixPlay(window, block, rate, flags) plays a block on a free one of 8
channels and returns the channel 1..8 (0 = error, LastError RD_ERR_BUSY all
busy, RD_ERR_NOTSUP no suitable card). The block stays locked while it
plays. flags: SM_LOOP endless, SM_16BIT signed 16 bit (otherwise unsigned
8 bit as in WAV), both mono, any rate from 1000 to 48000 Hz. End:
M_SOUNDDONE with p1 = 4, p2 = channel (not after SndMixStop).
  SndMixSet(k, vol, pan)     vol 0..127, pan 0 left, 64 centre, 127 right
  SndMixStop(k)              0 = all
  SndMixState(k)             1 = playing; k = 0: bits of playing channels
  SndMixOut(rate, MX_16BIT | MX_STEREO)   output, only what the card can do
Output: SB16/AWE 16 bit stereo, SB Pro 8 bit stereo, SB 2.0 and 1.x 8 bit
mono. Rate from RD2.INI [System] MixRate= (default 22050 from SB16, else
11025). The mixer (RDMIX.MOD) loads on first use and frees its buffer when
nothing plays. Mixing costs CPU time: no concern on 286 and 386, on the 8088
only a few channels at 11025 Hz. SndSamplePlay and the mixer exclude each
other (the later one wins). SB16: RD2.INI SB=A220 I5 D1 H5 (H = 16-bit DMA,
as in BLASTER). FM and mixer run together: music (SndMusicPlay) on FM,
effects as samples. On OPL3 (SB Pro 2 and up) SndNote has 18 channels:
music uses 0..8, 9..17 stay free for effects.

5d. Printing (all printers through one interface)
---------------------------------------------------------------
The program draws each page with the normal GDI functions into a printer
DC; RD2 rasterises it in bands and sends it to the driver from RD2.INI
[Drucker] (EPSON9 9 pins, ESCP24 24 pins/ESC/P2, PCL HP LaserJet and
DeskJet; chosen in Options, Printer tab).
  static PRNJOB j;  j.groesse = sizeof j; j.name = "Letter"; j.kopien = 1;
  j.flags = PJ_DIALOG;                 show the print dialog
  dc = PrnOpen(window, &j);            0 = error/cancel, LastError
  j.dpi_x, j.dpi_y, j.breite, j.hoehe  resolution and page in dots
  for (each page) {
      do { draw the page (always the whole page) }
      while ((r = PrnPage(dc)) == PRN_NOCHMAL);
      if (r) break;                    error, paper, cancel
  }
  PrnClose(dc);                        or PrnAbort(dc)
PrnPage returns PRN_NOCHMAL while the page must be drawn again for the next
band (or copy); just draw the same page again, RD2 sets the clipping.
PJ_ENTWURF: low resolution (faster), PJ_QUER landscape. Coordinates are
printer dots: compute sizes from dpi (1 cm = dpi_x * 10 / 254). Fonts scale
with the resolution. Example: apps/test/PRNTEST.C.

5e. Joystick
---------------------------------------------------------------
  JOYSTATE js;  if (JoyRead(0, &js)) ...   0 = joystick A, 1 = B
js.x, js.y -100..100 (centre 0, left/up negative), js.tasten bit 0 = fire 1,
bit 1 = fire 2. JoyCalibrate(0): current position is the centre. Without a
joystick 0, LastError RD_ERR_NOTSUP. Runs in RD2.LIB (game port 201h,
timed with the PIT, same values on XT and Pentium).

5f. FM sound (AdLib, OPL2/OPL3)
---------------------------------------------------------------
  static INSTR ins = { {mod 20h,40h,60h,80h,E0h}, {car ...}, feedback C0h };
  SndInstr(channel, &ins);             timbre for one channel
  SndNote(channel, note, vol);         note MIDI 0..127 (60 = middle C), vol 0..127
  SndNoteOff(channel);
OPL2 has 9 channels (0..8), OPL3 18. While music plays (SndMusicPlay) it owns
channels 0..8. Without an FM card SndNote plays on the PC speaker (one note
at a time). Simple tones: SndBeep(hz, ms); effects as samples (5c).

5g. Help (F1)
---------------------------------------------------------------
HelpShow(window, "PROG.HLP", topic) starts the help viewer with the file
from the program folder at the topic (number from the .HLP, 0 = contents).
.HLP format: docs/HILFE.md (German).



5h. Sounds for games (computed in advance, RD2 plays them)
---------------------------------------------------------------
No API calls are allowed in the tick callback (5a). A game therefore computes
its sounds once at start and hands them to RD2 as a memory block; RD2 plays,
mixes and pauses them on Alt+Tab. Choosing the device:
  c = SndCaps();
  if (c & SC_STREAM)              Sound Blaster: samples, SndMixPlay (5c)
  else if (c & (SC_OPL2|SC_OPL3)) AdLib/FM: SndMusicMem
  else                            PC speaker: SndTonePlay
  SndMusicMem(window, block, SM_IMF700)   IMF (type 0/1, 560/700/280 Hz) or DRO
                       from a block; RD2 copies it (may be freed afterwards).
                       End: M_SOUNDDONE p1 = 1 like SndMusicPlay. Replaces music.
  SndTonePlay(block, 0)  tone sequence: WORD pairs hz, ms (hz 0 = rest, ms 0 =
                       end, at most 64 pairs, 13.7 ms grid); replaces the running
                       sequence, an empty one = silence. On AdLib/SB an FM tone.
Example: RDISOENGINE src/rd2/rdrd2.c (Spritzwerkzeugbauer, all three paths).

6. Pascal
---------

Turbo Pascal 5.5-7.0 and Free Pascal (i8086-msdos, -WmLarge) work with the
unit RD2 (\SDK\PASCAL\RD2.PAS):

  TPC PHALLO.PAS
  RDRC - PHALLO.EXE "Hallo Pascal" /PAS

- RD2 must be the first unit in "uses". No Crt, Graph or screen Write.
- Memory with {$M stack,heapmin,heapmax}.
- Pointers, strings and records are passed as Pointer: GetClientRect(w, @r);
  Z('Text') turns a Pascal string into a zero-terminated one.
- Turbo Pascal 5.5 cannot discard function results: Egal := SetBkMode(...).
- Window procedures are far (TP: {$F+}) and pascal (FPC: "pascal;") and are
  always passed through CbProc:  wc.proc := CbProc(@Proc);
- /PAS puts a small preamble (about 900 bytes) in front of the program that
  gives the Pascal runtime the DOS start it expects.


7. More
-------


Kernel API versions
-------------------
KernVersion() returns (major << 8) | minor, RD2_API_VERSION in RD2.H.
Programs check KernVersion() >= ... before using new features.
  2.0  Function numbers reassigned (30.10.2026).
  2.1  MemError (0x042), MemStats (0x043): memory errors and swapping.
  2.2  IconDrawFile (0x0A1): draw the icon of an RD2 program file,
       WORD IconDrawFile(dc, x, y, file, id), 0 = file has no icon id.
       SM_HALBE for SndSamplePlay: message for each finished half of the
       block (M_SOUNDDONE, p1 = 3, p2 = half), see section 5.
  2.3  SysInfo (0x02F): machine information; BedarfCheck (0x030) and
       BEDARF in the .RC, see below.
  2.4  System timer TaktSet/TaktKill/TaktCount (0x032-0x034, section 5a),
       ScreenMouse (0x0E2, 5b), mixer SndMixPlay/Set/Stop/Out/State
       (0x127-0x12B, 5c), SndMusicMem and SndTonePlay (0x12C-0x12D, 5h).
       RD2.LIB: ScreenModeVesa, ScreenVesaList, ScreenPut
       (VESA for 16 bit, section Full screen). DirGet: buffer RD_DIRMAX bytes.
A program built for a newer API does not start on an older kernel
(RD_ERR_VERSION).

SysInfo (API 2.3)
-----------------
  static RDSYSDATA d; d.groesse = sizeof d; SysInfo(&d);
returns cpu (CPU_*), fpu, dos, kb_konv, kb_frei (largest free block for
programs), kb_ems and kb_xms (free, 0 = none), grafik (GFX_*), sound (SC_*
from RD2.INI Sound=), netz (1 = packet driver configured), maus, festplatte
(1 = RD2 runs from hard disk) and the 3D card: d3 (D3_*), d3_hersteller and
d3_geraet (PCI vendor/device). RD2SETUP detects the 3D card once via PCI
(386 and up) and writes 3D= and 3DPCI= to RD2.INI [System]; run RD2SETUP
again to redetect. Detected: 3dfx Voodoo 1 to 5, ATI Rage, Rage 128 and
newer, nVidia Riva 128, TNT and newer. groesse < 4 gives RD_ERR_HANDLE.
Later versions only append fields; older programs with a smaller groesse
get only their part.

BEDARF (API 2.3)
----------------
One line in the .RC states what the program needs:
  BEDARF CPU 386 FPU FARBEN 16 RAM 300 XMS 1024 KLANG PCM NETZ 3D BESCHLEUNIGER
Everything is optional. CPU 8088|8086|186|286|386|486|586, FPU = 8087 needed,
FARBEN 4|16|256 colours, RAM and XMS free KB, KLANG LAUTSPRECHER|OPL2|OPL3|PCM|
MIDI (may repeat, all needed), NETZ = packet driver, 3D SOFTWARE (386 and up)
or BESCHLEUNIGER (3D card as detected by RD2SETUP). The shell checks before
starting and says what is missing; in the "RD2 programs" menu a program is
greyed out when anything but memory is missing (memory counts at start).
BedarfCheck(file) returns the same check as a BD_* mask, 0 = fits or no
BEDARF. Programs without BEDARF run everywhere as before.

Packages: RDSETUP and SETUP.INF (API 2.3)
-----------------------------------------
A package folder with SETUP.INF is installed with RDSETUP (double-click
SETUP.INF in the shell) and removed via RDSETUP.LST in the target folder.
  [Paket]   Name=  Version=  Ziel=C:\GAMES\X  Programm=X.EXE
            Programm386=X32.EXE  Schreibtisch=1  Setup=OWN.EXE
  [Dateien] 1=X.EXE  2=X32.EXE 386  3=MUSIC.DAT KLANG  4=PIC.DAT FARBE
            5=GLIDE.DXE 3D  6=CALC.DAT 8087
Files whose condition is not met are not copied (so 32-bit parts never land
on machines below a 386). RDSETUP adds the program to PROGRAMM.LST.

Full screen (API 2.3)
---------------------
  if (ScreenAcquire(window) && ScreenMode(SM_13H, &si)) { ... draw at si.seg ... }
ScreenAcquire gives the program the whole screen: RD2 stops drawing, all keys
and mouse events go to the window. ScreenMode (RD2.LIB) sets SM_TEXT, SM_CGA4,
SM_EGA, SM_VGA16, SM_13H, SM_X (320x240) or SM_VESA (640x480, 64 KB window via
ScreenBank) and returns size, segment, bytes per line and planes. ScreenPalette
sets VGA colours (0..63) and remembers them. Alt+Tab or Alt+F6: RD2 parks the
window at the bottom, shows the desktop and sends M_SCREENLOST, then halts the
program (TaskHalt: no time slices, sound muted); it must not draw. Click on the parked window or
Alt+Tab: M_SCREENBACK, then ScreenRestore() (mode and palette as before) and
redraw from your own data. RD2 keeps no copy of the screen. ScreenRelease(window)
returns the screen (DestroyWindow and program exit do this too).
Example: apps/test/VOLLTEST.C.
VESA in 16-bit programs (RD2.LIB, API 2.4): ScreenModeVesa(800, 600, 16, &si)
picks a mode by size and colour depth (8, 15, 16, 24, 32); the card's list:
ScreenVesaList(list, max). In real mode always through window A (si.seg,
si.zeilenbytes): ScreenPut(x, y, w, h, src, srcline) copies a rectangle and
switches the 64 KB banks itself, ScreenBank(n) selects bank n in 64 KB units
(also on cards with 4 KB granularity). ScreenRestore restores the same VESA
mode after Alt+Tab. Example: apps/test/VESATEST.C. Complete example full
screen + mouse + keys + timer + sound + Alt+Tab, one source for 16 and 32
bit: apps/test/GESAMT.C.

RD2/32 programs (386 and up, disk "RD2 32", folder \SDK32)
---------------------------------------------------------------
32 bit, flat model, Open Watcom wcc386. The whole API from RD2.H applies
(pointers are 32-bit pointers), plus RD2_32.H: rd32_alloc/rd32_free (memory
above 1 MB), buffer bitmap BufCreate/BufShow, ScreenPtr and SM_LFB (VESA 2.0
linear). ScreenModeVesa(800, 600, 16, &si) picks a linear mode by size and
depth (8, 15, 16, 24, 32), ScreenVesaList lists the card's modes (example
VESA32.C). Without a linear frame buffer (VBE 1.2) ScreenModeVesa takes a
banked mode: ScreenPtr is then a shadow buffer and ScreenUpdate() copies it
to the screen; with LFB ScreenUpdate does nothing, so call it after every
frame. Needs a DPMI host: INSTALL adds CWSDPMI -p to CONFIG.SYS.

  wcc386 -bt=dos -mf -zl -zm -s -os FEN32.C
  wlink format raw bin name FEN32.B32 option offset=0,start=rd32_kopf,
        eliminate,nodefaultlibs file RD32C0,FEN32,RD32LIB,RD32PRG,RD32API
  wlink format dos name FEN32.EXE file RD2START,RD32STUB library RD2
  RDRC FEN32.RC FEN32.EXE "Fen32" /32:FEN32.B32

3D (RD3D.H, software): add "library RD3D,clib3r" when linking the image.
Example WUERFEL.C. C runtime (RD32C.LIB, headers in \SDK32\RD32C): stdio,
stdlib, string, ctype, setjmp, time, printf/sscanf with floating point;
compile with -fpc -i=RD32C, link "library RD32C,math3r,clib3r". printf
writes to the RD2 log, files go through the RD2 API. Example TESTC32.C.
32-bit modules (.M32): m = rd32_modload("X.M32"); f = rd32_modproc(m, "Name");
rd32_modfree(m). The module provides int RdMod32Init(void) (0 = ok), linked
with RD32M0 first; tools/rd32mod.py or under DOS MKM32 NAME (NAME.LNK,
NAME.EXP). Examples TESTM32.C and TESTMOD.C.

Memory protection (RD2 2.4): a program sees only its own memory (image,
stack, rd32_alloc, LFB). Any other access raises an exception: RD2 reports
it and ends only this program. Far pointers reach the rest:
  BYTE __far *b = BiosPtr();   b[0x46C] = timer ticks
  BYTE __far *v = LowPtr(0xB8000UL);   any address below 1 MB
In mode 13h and text mode ScreenPtr is a shadow buffer: call ScreenUpdate().
Drivers and diagnostics that must see everything link RD32C0V instead of
RD32C0. RD32C0 must come first. The .RC should contain BEDARF CPU 386.
Examples: FEN32.C (window, dialog, buffer bitmap, file, two tasks), VOLL32.C.

The full description (program format, modules, drivers, memory, limits) is in
docs/SPEC.md (German) in the RetroDesk 2 sources:
https://github.com/Karre-ops/RetroDesk2
